# ระบบกระทบยอดเบิกจ่าย OPD: HOSxP v4 เทียบ Statement สปสช.

เว็บแอปสำหรับเทียบรายการรับบริการ OPD ใน HOSxP v4 (PostgreSQL) กับไฟล์ REP / Statement ที่ดาวน์โหลดจาก e-Claim เพื่อหารายการที่ยังไม่ส่ง ถูกปฏิเสธ หรือได้รับชดเชยไม่ตรงยอด

| ส่วน | เทคโนโลยี |
|---|---|
| Backend | Node.js 20+, Express, pg, SheetJS, JWT (httpOnly cookie), bcrypt |
| ฐานข้อมูลของระบบ | PostgreSQL 15 (ฐาน `claim_recon` แยกจาก HOSxP) |
| Frontend | React 18 + Vite, Bootstrap 5, SweetAlert2, Chart.js |

## เริ่มต้นใช้งาน (เครื่องนักพัฒนา)

### 1. เตรียมฐานข้อมูล

```bash
# ใช้ Docker
docker compose up -d db          # PostgreSQL 15 ที่ localhost:5433

# หรือใช้ PostgreSQL ที่มีอยู่
createuser -P recon
createdb -O recon claim_recon
```

### 2. Backend

```bash
cd backend
cp .env.example .env             # แก้ค่า DB_*, HOSXP_*, JWT_SECRET, ADMIN_PASSWORD
npm install
npm run migrate                  # สร้างตาราง
npm run seed                     # สร้าง admin และรูปแบบไฟล์เริ่มต้น
npm run dev                      # http://localhost:4000
```

> `xlsx` ติดตั้งจาก `cdn.sheetjs.com` (เวอร์ชันบน npm เก่าและมีช่องโหว่ที่รู้จักแล้ว) เครื่องที่ติดตั้งต้องออกอินเทอร์เน็ตไปโดเมนนี้ได้

### 3. Frontend

```bash
cd frontend
npm install
npm run dev                      # http://localhost:5173 (ส่ง /api ต่อไปที่ :4000 ให้อัตโนมัติ)
```

เข้าสู่ระบบด้วย `ADMIN_USERNAME` / `ADMIN_PASSWORD` จาก `.env` แล้ว **เปลี่ยนรหัสผ่านทันที**

### ทดลองโดยไม่ต่อ HOSxP จริง

```bash
createdb hos_mock
psql -d hos_mock -f backend/db/dev/mock_hosxp.sql
# ตั้ง HOSXP_DB=hos_mock ใน .env
```

จากนั้นนำเข้า `samples/sample_rep_opd_2569-09.xlsx` และดึงข้อมูล HOSxP ช่วง 1–30 ก.ย. 2569 (2026) จะเห็นผลครบทุกสถานะ

## การเชื่อมต่อ HOSxP v4

สร้าง user อ่านอย่างเดียว (แนะนำให้ต่อที่เครื่อง replica):

```sql
CREATE ROLE claim_reader LOGIN PASSWORD 'รหัสที่แข็งแรง';
GRANT CONNECT ON DATABASE hos TO claim_reader;
GRANT USAGE ON SCHEMA public TO claim_reader;
GRANT SELECT ON vn_stat, patient, pttype, opitemrece, nondrugitems, drugitems, ovstdiag TO claim_reader;
```

ระบบตั้ง `default_transaction_read_only=on` ให้ทุก connection ของ HOSxP อีกชั้นหนึ่ง

query อยู่ที่ `backend/src/services/hosxpService.js` ที่เดียว ใช้ฟิลด์ `vn_stat (vn, hn, vstdate, pttype, pdx, income, uc_money)`, `patient (cid, pname, fname, lname)` และ `pttype (name, hipdata_code)` หากรพ.ปรับแต่งโครงสร้าง ให้ตรวจด้วย `\d vn_stat` แล้วแก้ที่ไฟล์นี้

## หลักการทำงาน

1. **นำเข้าไฟล์ สปสช.** ระบบหาแถวหัวตารางเอง จับคู่คอลัมน์ตาม "รูปแบบไฟล์" ที่ admin กำหนด แสดงตัวอย่างและแถวที่มีปัญหาก่อนบันทึก รายการที่มี TRAN_ID เดิมจะถูกอัปเดต ไม่เพิ่มซ้ำ
2. **ดึงข้อมูล HOSxP** ตามช่วงวันที่ (ไม่เกิน 93 วันต่อครั้ง) แทนที่ snapshot เดิมของช่วงนั้นทั้งหมด
3. **กระทบยอด** จับคู่ด้วย เลขบัตรประชาชน + วันที่รับบริการ ถ้าผู้ป่วยมาหลายครั้งในวันเดียว ระบบจับคู่ 1:1 ตามลำดับยอดเงินและติดสถานะให้ตรวจสอบ

| สถานะ | ความหมาย |
|---|---|
| ตรงกัน | พบทั้งสองฝั่ง ยอดเท่ากัน |
| ยอดต่าง | พบทั้งสองฝั่ง ยอดไม่เท่ากัน (เลือกได้ว่าเทียบกับยอดเรียกเก็บหรือยอดชดเชย) |
| ถูกปฏิเสธ / ติด C | มีรหัสข้อผิดพลาดจาก สปสช. |
| หลายครั้งในวันเดียว | จับคู่ตามลำดับยอดเงิน ควรตรวจด้วยคน |
| ไม่พบใน Statement | มีใน HOSxP แต่ยังไม่มีผลจาก สปสช. |
| ไม่พบใน HOSxP | มีใน Statement แต่หาใน HOSxP ไม่เจอ |

## ไฟล์ที่นำเข้า: REP จาก e-Claim

ระบบนำเข้าไฟล์ REP (ผลการตรวจสอบรายการเบิก) ชีต `Detail` รูปแบบไฟล์ "e-Claim REP OPD (ชีต Detail)" สร้างโดย migration 011

- หัวตาราง 3 ชั้น (แถว 6-8) ระบบตั้งชื่อคอลัมน์แบบ `กลุ่ม / คอลัมน์ย่อย` เช่น `ค่าใช้จ่ายสูง (HC) / OPHC`
- ยอดชดเชย = "ชดเชยสุทธิ" (สปสช. + ต้นสังกัด) ยอดเรียกเก็บ = "รวมยอดเรียกเก็บ (1.3)"
- สถานะ "ถูกปฏิเสธ" ตัดสินจาก Error Code (ยังไม่ใช้คอลัมน์ Deny)
- รายการประเภทผู้ป่วย IP ในไฟล์ OPD ถูกข้าม
- รอบของรายการ = เลขที่ REP เดือนของรอบอ่านจากเลข REP (เช่น 690900086 = ก.ย. 2569)
- ชีต `Data Drug` และ `Summary` ไม่ได้ใช้
- ข้อมูล Statement เดิม (ก่อนเปลี่ยนมาใช้ REP) ลบได้ที่หน้านำเข้าไฟล์ (admin) ไม่ควรใช้คู่กับ REP เพราะยอดจะนับซ้ำ

กองทุน FS (Fee Schedule) และ DRUG (ค่ายา) เป็นแบบ "ติดตามยอดรับ" ไม่ต้องตั้งรายการ นับเฉพาะยอดที่ได้รับจาก REP และไม่คำนวณอัตราการส่งเบิก

## Statement / REP หลายรอบ

ระบบอ่านเลขที่เอกสาร STM จากหัวรายงาน (เช่น `เลขที่เอกสาร 11344 OPUCS256908 01`) หรือจากชื่อไฟล์ แล้วเก็บรายการของแต่ละรอบแยกกัน
นำเข้าไฟล์เดิมซ้ำจะอัปเดตรายการเดิม ไม่เพิ่มซ้ำ เวลาแสดงผลระบบรวมทุกรอบของ visit เดียวกัน:

- TRAN_ID เดียวกันข้ามรอบ (เช่น ยอดปรับลดติดลบ) รวมยอดชดเชยและยอดกองทุนสุทธิ
- คนไข้มี visit เดียวในวันนั้น รวมทุกรายการของวันนั้น รวมกรณีส่งใหม่ได้ TRAN_ID ใหม่
- รหัสข้อผิดพลาดใช้ของรอบล่าสุด
- visit ที่ไม่มีเลขบัตรประชาชนใน HOSxP จับคู่ด้วย HN + วันที่แทน

## แยกกองทุน OPD

แยก visit ตามกองทุนของ Statement (HC, ค่ายามะเร็ง, AE, INST, DMIS ฯลฯ) จากรายการค่าบริการ/ยาที่คนไข้ได้รับ

1. **ตั้งค่ากองทุน** (admin) ที่เมนู "ตั้งค่ากองทุน" ค้นหารายการจาก `nondrugitems` (ค่าบริการ) หรือ `drugitems` (ยา) แล้วเพิ่มเข้ากองทุน visit จะเข้าเกณฑ์เมื่อมีรายการเหล่านี้ **อย่างน้อย 1 รายการ** และสิทธิตรงเงื่อนไข:
   - **กลุ่มสิทธิ** (`hipdata_code`) ค่าเริ่มต้น UCS นับทุกรหัสสิทธิในกลุ่ม รวมรหัสที่เพิ่มใหม่ใน HOSxP ภายหลัง
   - **รหัสสิทธิรายตัว** (`pttype`) ถ้าเลือกไว้ จะใช้แทนกลุ่มสิทธิ
   - กลุ่มใน `EXCLUDED_HIPDATA` (`.env`, ค่าเริ่มต้น `XXX` = ชำระเงินเอง) ไม่นับเข้ากองทุนใดเสมอ การดึงข้อมูล HOSxP ยังดึงทุกสิทธิ เพื่อให้ตรวจย้อนกลับเห็นกรณีสิทธิใน HOSxP ไม่ตรงกับที่ได้รับเงิน รายการให้เลือกแสดงเฉพาะที่ใช้งานอยู่ (`istatus = 'Y'` สำหรับค่าบริการและยา, `isuse = 'Y'` สำหรับสิทธิ)
2. **กำหนดคอลัมน์ยอดที่ได้รับ** ของแต่ละกองทุนในไฟล์ REP หัวตารางหลายชั้นเขียนแบบ `กลุ่ม / คอลัมน์ย่อย` เช่น `HC / HC` หลายคอลัมน์จะรวมยอดให้ ดูชื่อที่ถูกต้องได้จาก "หัวคอลัมน์ทั้งหมดในไฟล์" ในหน้าตรวจไฟล์
3. **นำเข้าไฟล์ REP** (หรือนำเข้าซ้ำหลังแก้คอลัมน์) ระบบจะอ่านยอดรายกองทุนเก็บไว้
4. **ดึงข้อมูล HOSxP** ระบบดึงรายการจาก `opitemrece` เฉพาะ icode ที่ตั้งค่าไว้ เพิ่มรายการใหม่ในกองทุนแล้วต้องดึงใหม่
5. **ดูผล** ที่เมนู "แยกกองทุน OPD" มี 3 ส่วน
   - สรุปรายกองทุน: คนไข้ (ไม่ซ้ำ), visit, ยอดตั้งเบิก, ยอดเบิกได้ และจำนวนตามสถานะ ได้รับเงิน, ไม่ได้รับเงินกองทุนนี้, ถูกปฏิเสธ / ติด C, ไม่พบใน Statement
   - ตรวจย้อนกลับ: รายการที่ สปสช. จ่ายเงินกองทุนแต่ไม่เข้าเกณฑ์ตามการตั้งค่า พร้อมเหตุผล (ไม่มีรายการที่ตั้งค่า, สิทธิไม่อยู่ในเงื่อนไข, ไม่พบ visit ใน HOSxP) ใช้หารายการที่ยังขาดในการตั้งค่า
   - สรุปรายเดือน: ตารางและกราฟของกองทุนที่เลือก (หรือทุกกองทุน) ตลอดช่วงวันที่ เช่น ทั้งปีงบประมาณ

### วิเคราะห์รายการ (แท็บในหน้าแยกกองทุน)

- **รายการจำเป็น:** ติ๊ก "จำเป็น" ที่รายการในหน้าตั้งค่ากองทุน คอลัมน์ "ขาดรายการ" จะแจ้งว่า visit ใดขาดรายการจำเป็นตัวไหน
- **อัตราได้รับเงินรายรายการ:** แต่ละรายการที่ตั้งค่าพบในกี่ visit ได้รับเงินกี่ visit
- **เทียบกับเคสที่ได้รับเงิน:** รายการ (ทุกรายการของ visit รวมที่ไม่ได้ตั้งค่า) ที่พบในเคสได้รับเงินตั้งแต่ 60% ขึ้นไป เทียบกับเคสที่ไม่สำเร็จ ต้องมีเคสได้รับเงินอย่างน้อย 5 visit ปรับเกณฑ์ได้ที่ `MIN_PAID` และ `COMMON_RATE` ใน `fundService.js`

การดึงข้อมูล HOSxP ดึงทุกรายการค่าใช้จ่ายเฉพาะของ visit ที่มีรายการตามกองทุนอย่างน้อย 1 รายการ

query ของ HOSxP สำหรับส่วนนี้อยู่ที่ `ITEMS_SQL`, `SEARCH_SQL` และ `ACTIVE` ใน `hosxpService.js` ชื่อคอลัมน์สถานะใช้งานกำหนดที่ `ACTIVE` จุดเดียว

## วิธีคัด visit เข้ากองทุน

แต่ละกองทุนเลือกได้ 2 แบบ
- **รายการค่าบริการ/ยา + สิทธิ** (ค่าเริ่มต้น เช่น HC, AE, INST) visit ต้องมีรายการที่ตั้งไว้อย่างน้อย 1 รายการ
- **สิทธิอย่างเดียว** (เช่น OFC) ทุก visit ของสิทธิที่เลือกที่มียอดเรียกเก็บ (`uc_money` > 0) ยอดตั้งเบิก = `uc_money` ของ visit

สิทธิที่เข้าเงื่อนไขเลือกได้ 2 แบบ: ตามกลุ่มสิทธิ (`hipdata_code` นับรหัสใหม่ในกลุ่มให้อัตโนมัติ) หรือเลือกรหัสสิทธิเอง

## เงื่อนไขรหัสโรค (ICD-10)

แต่ละกองทุนกำหนดรหัส ICD-10 ได้ (รหัสเต็มหรือขึ้นต้น เช่น `H25` นับ H250-H259 มีจุดหรือไม่มีก็ได้) ใช้ร่วมกับเงื่อนไขรายการ/สิทธิ
เลือกได้ว่าเทียบเฉพาะโรคหลัก (PDX) หรือโรคหลักและโรครอง รหัสวินิจฉัยทุกตัวดึงจากตาราง `ovstdiag` ของ HOSxP เก็บใน `his_opd_dx`

## รหัสข้อผิดพลาด e-Claim

ระบบมีตารางรหัสข้อผิดพลาดตั้งต้น 607 รหัส (migration 014 สร้างจาก `db/seed/eclaim_error_codes.tsv`)
แก้ไขหรือเพิ่มรหัสได้ที่เมนู "รหัสข้อผิดพลาด" หรือแก้ไฟล์ .tsv แล้วสร้าง migration ใหม่ด้วย `npm run build:error-codes -- 0XX_error_codes_update.sql`
นำเข้าเพิ่มจากตารางอ้างอิงได้โดยคัดลอกตาราง (รหัส, รายละเอียด, แนวทางแก้ไข คั่นด้วยแท็บ) มาวาง หน้ากระทบยอด OPD และไฟล์ส่งออกจะแสดงรายละเอียดและแนวทางแก้ไขของแต่ละรหัส รองรับค่าใน REP แบบ `438`, `C438` และหลายรหัสในช่องเดียว

## ส่งออกรายงาน

เมนู "ส่งออกรายงาน" ให้เจ้าหน้าที่ผู้รับผิดชอบกองทุนส่งออก Excel ไปใช้แก้ไขต่อ มี 6 ประเภท: คนไข้ที่เข้าเกณฑ์, ยังไม่ส่งเบิก, เคลมไม่สำเร็จ, ข้อมูลอาจไม่ครบถ้วน, ได้รับเงินแล้ว และได้รับเงินแต่ไม่เข้าเกณฑ์

- ไฟล์มีชีต "สรุป" (เงื่อนไขรายงาน ผู้ส่งออก จำนวนต่อกองทุน) และชีตข้อมูล แยกตามกองทุนได้ หัวตารางมีตัวกรอง
- คอลัมน์ "ประเด็นที่ควรตรวจ" รวมปัญหาที่พบ: ไม่มีเลขบัตร/ไม่ครบ 13 หลัก, ไม่มี PDX, ขาดรายการจำเป็น, ขาดรายการที่เคสได้รับเงินมักมี, ถูกปฏิเสธ
- คอลัมน์ว่าง "ผลการแก้ไข / หมายเหตุ" ให้เจ้าหน้าที่กรอก
- admin กำหนด "กองทุนที่รับผิดชอบ" ของผู้ใช้ได้ในหน้าผู้ใช้งาน หน้าส่งออกจะเลือกกองทุนเหล่านั้นไว้ให้ (ไม่ได้จำกัดสิทธิ์การดูข้อมูล)
- ทุกการส่งออกถูกบันทึกใน `access_logs`

## แดชบอร์ดภาพรวม (ตัวชี้วัด)

หน้าแรกแสดงตัวชี้วัดการเบิกของปีงบประมาณที่เลือก

| ตัวชี้วัด | วิธีคิด |
|---|---|
| อัตราการส่งเบิก | visit ที่เข้าเกณฑ์และพบใน Statement ÷ visit ที่เข้าเกณฑ์ |
| อัตราเคลมสำเร็จ | ได้รับเงิน ÷ ที่พบใน Statement |
| ความครบถ้วนของข้อมูล | visit ที่มีเลขบัตร 13 หลัก มี PDX และไม่ขาดรายการจำเป็น ÷ visit ที่เข้าเกณฑ์ |
| ยอดที่ยังไม่ส่งเบิก | ยอดตั้งเบิกของ visit ที่ไม่พบใน Statement (เดือนที่ปิดยอดแล้ว) |
| ยอดเบิกได้ | ยอดกองทุนจาก Statement ทุกรอบ |

- ตัวชี้วัดคิดเฉพาะ "เดือนที่ปิดยอดแล้ว" คือเดือนที่มีรายการใน Statement ที่นำเข้า เดือนที่ยังไม่มีแสดงเป็น "รอผล" เพราะ Statement มาช้ากว่าวันรับบริการ
- เป้าหมายตั้งได้รายกองทุนในหน้าตั้งค่ากองทุน (ค่าเริ่มต้น ส่งเบิก 95%, เคลมสำเร็จ 90%, ครบถ้วน 95%) สี: ถึงเป้า = เขียว, ต่ำกว่าไม่เกิน 10 จุด = เหลือง, ต่ำกว่านั้น = แดง
- ผลคำนวณถูกเก็บในหน่วยความจำ และคำนวณใหม่เมื่อมีการนำเข้า ดึงข้อมูล หรือแก้การตั้งค่า

## ติดตั้งใช้งานจริง

```bash
cp backend/.env.example backend/.env   # ตั้ง NODE_ENV=production และ JWT_SECRET ใหม่
docker compose up -d --build
docker compose exec app node scripts/seed.js
```

แอปเปิดที่พอร์ต 4000 (Express เสิร์ฟทั้ง API และหน้าเว็บ) ควรวางหลัง nginx ที่ใช้ HTTPS และตั้ง `TRUST_PROXY=1` ใน `.env` เมื่อใช้ production cookie จะถูกตั้งเป็น `secure` จึงต้องเข้าผ่าน HTTPS

## ความปลอดภัยและ PDPA

ข้อมูลไม่ออกนอกเครือข่ายรพ. ไฟล์ที่อัปโหลดประมวลผลในหน่วยความจำ ไม่เขียนลงดิสก์ token เก็บใน httpOnly cookie แบบ SameSite=strict มีการจำกัดการลอง login และทุกการดูผล ส่งออก นำเข้า และดึงข้อมูล ถูกบันทึกในตาราง `access_logs`

## งานถัดไปที่แนะนำ

ฝั่ง IPD (จับคู่ด้วย AN จาก `an_stat`), บันทึกการติดตามรายรายการ, กราฟแนวโน้มรายเดือน และนำเข้าหลายไฟล์พร้อมกัน
