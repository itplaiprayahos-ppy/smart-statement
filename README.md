# ระบบกระทบยอดเบิกจ่าย OPD: HOSxP v4 เทียบ Statement สปสช.

เว็บแอปสำหรับเทียบรายการรับบริการ OPD ใน HOSxP v4 (PostgreSQL) กับไฟล์ REP / Statement ที่ดาวน์โหลดจาก e-Claim เพื่อหารายการที่ยังไม่ส่ง ถูกปฏิเสธ หรือได้รับชดเชยไม่ตรงยอด

| ส่วน | เทคโนโลยี |
|---|---|
| Backend | Node.js 20+, Express, pg, SheetJS, JWT (httpOnly cookie), bcrypt |
| ฐานข้อมูลของระบบ | PostgreSQL 15 (ฐาน `claim_recon` แยกจาก HOSxP) |
| Frontend | React 18 + Vite, Bootstrap 5, SweetAlert2, Chart.js |

## เริ่มต้นใช้งาน (เครื่องนักพัฒนา)

### 1. เตรียมฐานข้อมูล

```bash
# ใช้ Docker
docker compose up -d db          # PostgreSQL 15 ที่ localhost:5433

# หรือใช้ PostgreSQL ที่มีอยู่
createuser -P recon
createdb -O recon claim_recon
```

### 2. Backend

```bash
cd backend
cp .env.example .env             # แก้ค่า DB_*, HOSXP_*, JWT_SECRET, ADMIN_PASSWORD
npm install
npm run migrate                  # สร้างตาราง
npm run seed                     # สร้าง admin และรูปแบบไฟล์เริ่มต้น
npm run dev                      # http://localhost:4000
```

> `xlsx` ติดตั้งจาก `cdn.sheetjs.com` (เวอร์ชันบน npm เก่าและมีช่องโหว่ที่รู้จักแล้ว) เครื่องที่ติดตั้งต้องออกอินเทอร์เน็ตไปโดเมนนี้ได้

### 3. Frontend

```bash
cd frontend
npm install
npm run dev                      # http://localhost:5173 (ส่ง /api ต่อไปที่ :4000 ให้อัตโนมัติ)
```

เข้าสู่ระบบด้วย `ADMIN_USERNAME` / `ADMIN_PASSWORD` จาก `.env` แล้ว **เปลี่ยนรหัสผ่านทันที**

## การเชื่อมต่อ HOSxP v4

สร้าง user อ่านอย่างเดียว (แนะนำให้ต่อที่เครื่อง replica):

```sql
CREATE ROLE claim_reader LOGIN PASSWORD 'รหัสที่แข็งแรง';
GRANT CONNECT ON DATABASE hos TO claim_reader;
GRANT USAGE ON SCHEMA public TO claim_reader;
GRANT SELECT ON vn_stat, patient, pttype, opitemrece, nondrugitems, drugitems, ovstdiag, kskdepartment TO claim_reader;
```

ระบบตั้ง `default_transaction_read_only=on` ให้ทุก connection ของ HOSxP อีกชั้นหนึ่ง

query อยู่ที่ `backend/src/services/hosxpService.js` ที่เดียว ใช้ฟิลด์ `vn_stat (vn, hn, vstdate, pttype, pdx, income, uc_money)`, `patient (cid, pname, fname, lname)` และ `pttype (name, hipdata_code)` หากรพ.ปรับแต่งโครงสร้าง ให้ตรวจด้วย `\d vn_stat` แล้วแก้ที่ไฟล์นี้

## ยอดเงินจาก HOSxP (v36)

ตั้งแต่ v36 ระบบคำนวณยอดของ visit จาก `opitemrece` ตอนดึงข้อมูล แทนการอ่าน `vn_stat.income / uc_money`
เพราะ `vn_stat` คำนวณไว้ ณ จุดเวลาหนึ่ง รายการที่เพิ่มหรือแก้ทีหลังไม่ตามมา (พบ visit ที่ `uc_money` = 0 ทั้งที่มีรายการลูกหนี้สิทธิ)

| ค่า | ที่มา |
|---|---|
| ค่าใช้จ่ายทั้ง visit (`income`) | รวม `sum_price` ทุกรายการของ visit |
| เรียกเก็บ (HOSxP) (`uc_money`) | รวมรายการที่ `paidst` อยู่ใน `HOSXP_CLAIM_PAIDST` (ค่าเริ่มต้น `02` ลูกหนี้สิทธิ) |

paidst ของ HOSxP: 00 ค้างชำระ · 01 ชำระเองเบิกได้ · 02 ลูกหนี้สิทธิ · 03 ชำระเองเบิกไม่ได้ · 04 ส่วนลดเงินสด
visit ที่ไม่มีรายการใน `opitemrece` ใช้ค่าจาก `vn_stat` ถ้าต้องการกลับไปใช้ `vn_stat` ตั้ง `HOSXP_AMOUNT_SOURCE=vn_stat` ใน `.env`
หลังอัปเดตต้อง **ดึงข้อมูล HOSxP ใหม่** ทุกช่วงที่ใช้งาน ยอดเดิมในระบบจึงจะเปลี่ยน

## หลักการทำงาน

1. **นำเข้าไฟล์ สปสช.** ระบบหาแถวหัวตารางเอง จับคู่คอลัมน์ตาม "รูปแบบไฟล์" ที่ admin กำหนด แสดงตัวอย่างและแถวที่มีปัญหาก่อนบันทึก รายการที่มี TRAN_ID เดิมจะถูกอัปเดต ไม่เพิ่มซ้ำ
2. **ดึงข้อมูล HOSxP** ตามช่วงวันที่ (ไม่เกิน 93 วันต่อครั้ง) แทนที่ snapshot เดิมของช่วงนั้นทั้งหมด
3. **กระทบยอด** จับคู่ด้วย เลขบัตรประชาชน + วันที่รับบริการ ถ้าผู้ป่วยมาหลายครั้งในวันเดียว ระบบจับคู่ 1:1 ตามลำดับยอดเงินและติดสถานะให้ตรวจสอบ

| สถานะ | ความหมาย |
|---|---|
| ตรงกัน | พบทั้งสองฝั่ง ยอดเท่ากัน |
| ยอดต่าง | พบทั้งสองฝั่ง ยอดไม่เท่ากัน (เลือกได้ว่าเทียบกับยอดเรียกเก็บหรือยอดชดเชย) |
| ถูกปฏิเสธ / ติด C | มีรหัสข้อผิดพลาดจาก สปสช. |
| หลายครั้งในวันเดียว | จับคู่ตามลำดับยอดเงิน ควรตรวจด้วยคน |
| ไม่พบใน Statement | มีใน HOSxP แต่ยังไม่มีผลจาก สปสช. |
| ไม่พบใน HOSxP | มีใน Statement แต่หาใน HOSxP ไม่เจอ |

## ไฟล์ที่นำเข้า: REP จาก e-Claim

ระบบนำเข้าไฟล์ REP (ผลการตรวจสอบรายการเบิก) ชีต `Detail` รูปแบบไฟล์ "e-Claim REP OPD (ชีต Detail)" สร้างโดย migration 011

- หัวตาราง 3 ชั้น (แถว 6-8) ระบบตั้งชื่อคอลัมน์แบบ `กลุ่ม / คอลัมน์ย่อย` เช่น `ค่าใช้จ่ายสูง (HC) / OPHC`
- ยอดชดเชย = "ชดเชยสุทธิ" (สปสช. + ต้นสังกัด) ยอดเรียกเก็บ = "รวมยอดเรียกเก็บ (1.3)"
- สถานะ "ถูกปฏิเสธ" ตัดสินจาก Error Code (ยังไม่ใช้คอลัมน์ Deny)
- รายการประเภทผู้ป่วย IP ในไฟล์ OPD ถูกข้าม
- รอบของรายการ = เลขที่ REP เดือนของรอบอ่านจากเลข REP (เช่น 690900086 = ก.ย. 2569)
- ชีต `Data Drug` และ `Summary` ไม่ได้ใช้
- ข้อมูล Statement เดิม (ก่อนเปลี่ยนมาใช้ REP) ลบได้ที่หน้านำเข้าไฟล์ (admin) ไม่ควรใช้คู่กับ REP เพราะยอดจะนับซ้ำ

กองทุน FS (Fee Schedule) และ DRUG (ค่ายา) เป็นแบบ "ติดตามยอดรับ" ไม่ต้องตั้งรายการ นับเฉพาะยอดที่ได้รับจาก REP และไม่คำนวณอัตราการส่งเบิก

## Statement / REP หลายรอบ

ระบบอ่านเลขที่เอกสาร STM จากหัวรายงาน (เช่น `เลขที่เอกสาร 11344 OPUCS256908 01`) หรือจากชื่อไฟล์ แล้วเก็บรายการของแต่ละรอบแยกกัน
นำเข้าไฟล์เดิมซ้ำจะอัปเดตรายการเดิม ไม่เพิ่มซ้ำ เวลาแสดงผลระบบรวมทุกรอบของ visit เดียวกัน:

- TRAN_ID เดียวกันข้ามรอบ (เช่น ยอดปรับลดติดลบ) รวมยอดชดเชยและยอดกองทุนสุทธิ
- คนไข้มี visit เดียวในวันนั้น รวมทุกรายการของวันนั้น รวมกรณีส่งใหม่ได้ TRAN_ID ใหม่
- รหัสข้อผิดพลาดใช้ของรอบล่าสุด
- visit ที่ไม่มีเลขบัตรประชาชนใน HOSxP จับคู่ด้วย HN + วันที่แทน

## แยกกองทุน OPD

แยก visit ตามกองทุนของ Statement (HC, ค่ายามะเร็ง, AE, INST, DMIS ฯลฯ) จากรายการค่าบริการ/ยาที่คนไข้ได้รับ

1. **ตั้งค่ากองทุน** (admin) ที่เมนู "ตั้งค่ากองทุน" ค้นหารายการจาก `nondrugitems` (ค่าบริการ) หรือ `drugitems` (ยา) แล้วเพิ่มเข้ากองทุน visit จะเข้าเกณฑ์เมื่อมีรายการเหล่านี้ **อย่างน้อย 1 รายการ** และสิทธิตรงเงื่อนไข:
   - **รหัสสิทธิ** (`pttype`) ติ๊กรายตัว ใช้ปุ่มกลุ่มสิทธิ (`hipdata_code`) กรองตารางแล้วกด "เลือกที่แสดงทั้งหมด" เพื่อเลือกทั้งกลุ่ม ไม่เลือกเลย = ทุกสิทธิ
   - กองทุนที่เคยตั้งแบบกลุ่มสิทธิ (รุ่นก่อน) ยังทำงานตามกลุ่มเดิม เมื่อเปิดแก้ไขระบบจะติ๊กรหัสในกลุ่มนั้นให้ และเก็บเป็นรายการรหัสเมื่อบันทึก
   - กลุ่มใน `EXCLUDED_HIPDATA` (`.env`, ค่าเริ่มต้น `XXX` = ชำระเงินเอง) ไม่นับเข้ากองทุนใดเสมอ การดึงข้อมูล HOSxP ยังดึงทุกสิทธิ เพื่อให้ตรวจย้อนกลับเห็นกรณีสิทธิใน HOSxP ไม่ตรงกับที่ได้รับเงิน รายการให้เลือกแสดงเฉพาะที่ใช้งานอยู่ (`istatus = 'Y'` สำหรับค่าบริการและยา, `isuse = 'Y'` สำหรับสิทธิ)
2. **กำหนดคอลัมน์ยอดที่ได้รับ** ของแต่ละกองทุนในไฟล์ REP หัวตารางหลายชั้นเขียนแบบ `กลุ่ม / คอลัมน์ย่อย` เช่น `HC / HC` หลายคอลัมน์จะรวมยอดให้ ดูชื่อที่ถูกต้องได้จาก "หัวคอลัมน์ทั้งหมดในไฟล์" ในหน้าตรวจไฟล์
3. **นำเข้าไฟล์ REP** (หรือนำเข้าซ้ำหลังแก้คอลัมน์) ระบบจะอ่านยอดรายกองทุนเก็บไว้
4. **ดึงข้อมูล HOSxP** ระบบดึงรายการจาก `opitemrece` เฉพาะ icode ที่ตั้งค่าไว้ เพิ่มรายการใหม่ในกองทุนแล้วต้องดึงใหม่
5. **ดูผล** ที่เมนู "แยกกองทุน OPD" มี 3 ส่วน
   - สรุปรายกองทุน: คนไข้ (ไม่ซ้ำ), visit, ยอดตั้งเบิก, ยอดเบิกได้ และจำนวนตามสถานะ ได้รับเงิน, ไม่ได้รับเงินกองทุนนี้, ถูกปฏิเสธ / ติด C, ไม่พบใน Statement
   - ตรวจย้อนกลับ: รายการที่ สปสช. จ่ายเงินกองทุนแต่ไม่เข้าเกณฑ์ตามการตั้งค่า พร้อมเหตุผล (ไม่มีรายการที่ตั้งค่า, สิทธิไม่อยู่ในเงื่อนไข, ไม่พบ visit ใน HOSxP) ใช้หารายการที่ยังขาดในการตั้งค่า
   - สรุปรายเดือน: ตารางและกราฟของกองทุนที่เลือก (หรือทุกกองทุน) ตลอดช่วงวันที่ เช่น ทั้งปีงบประมาณ

### วิเคราะห์รายการ (แท็บในหน้าแยกกองทุน)

- **รายการจำเป็น:** ติ๊ก "จำเป็น" ที่รายการในหน้าตั้งค่ากองทุน คอลัมน์ "ขาดรายการ" จะแจ้งว่า visit ใดขาดรายการจำเป็นตัวไหน
- **อัตราได้รับเงินรายรายการ:** แต่ละรายการที่ตั้งค่าพบในกี่ visit ได้รับเงินกี่ visit
- **เทียบกับเคสที่ได้รับเงิน:** รายการ (ทุกรายการของ visit รวมที่ไม่ได้ตั้งค่า) ที่พบในเคสได้รับเงินตั้งแต่ 60% ขึ้นไป เทียบกับเคสที่ไม่สำเร็จ ต้องมีเคสได้รับเงินอย่างน้อย 5 visit ปรับเกณฑ์ได้ที่ `MIN_PAID` และ `COMMON_RATE` ใน `fundService.js`

การดึงข้อมูล HOSxP ดึงทุกรายการค่าใช้จ่ายเฉพาะของ visit ที่มีรายการตามกองทุนอย่างน้อย 1 รายการ

query ของ HOSxP สำหรับส่วนนี้อยู่ที่ `ITEMS_SQL`, `SEARCH_SQL` และ `ACTIVE` ใน `hosxpService.js` ชื่อคอลัมน์สถานะใช้งานกำหนดที่ `ACTIVE` จุดเดียว

## วิธีคัด visit เข้ากองทุน

แต่ละกองทุนเลือกได้ 3 แบบ (ทุกแบบกรองด้วยสิทธิการรักษาที่เลือก)
- **ค่าบริการ** (ค่าเริ่มต้น เช่น HC, AE, INST) มีรายการค่าบริการ/ยาที่ตั้งไว้อย่างน้อย 1 รายการ กรองเพิ่มด้วย ICD-10 ได้
- **สิทธิการรักษา** (เช่น OFC) ทุก visit ของสิทธิที่เลือกที่มียอดเรียกเก็บ (`uc_money` > 0)
- **ICD-10** ทุก visit ที่มีรหัสโรคตามที่กำหนดและมียอดเรียกเก็บ
แบบสิทธิการรักษาและ ICD-10 ใช้ยอดตั้งเบิก = `uc_money` ของ visit

สิทธิที่เข้าเงื่อนไขเลือกเป็นรายการรหัสสิทธิ โดยกรองตามกลุ่มสิทธิ (`hipdata_code`) ได้

## เงื่อนไขรหัสโรค (ICD-10)

แต่ละกองทุนกำหนดรหัส ICD-10 ได้ทั้งรหัสเดี่ยวและช่วง (มีจุดหรือไม่มีก็ได้) ใช้ร่วมกับเงื่อนไขรายการ/สิทธิ
- รหัสเดี่ยว = ขึ้นต้นด้วย เช่น `H25` นับ H250-H259
- ช่วง = เทียบตามความยาวของรหัสที่ใส่ เช่น `C00-C96` นับ C000-C969, `C50.1-C50.9` เทียบ 4 ตัวแรก
เลือกได้ว่าเทียบเฉพาะโรคหลัก (PDX) หรือโรคหลักและโรครอง รหัสวินิจฉัยทุกตัวดึงจากตาราง `ovstdiag` ของ HOSxP เก็บใน `his_opd_dx`

## รหัสข้อผิดพลาด e-Claim

## รายชื่อคนไข้ (v35: รวมกระทบยอด OPD, แยกกองทุน OPD และเทียบ 3 แหล่ง)

เมนู "รายชื่อคนไข้" (`/patients`) ใช้แทน 3 เมนูเดิม (หน้าเดิมยังเปิดได้จากลิงก์ท้ายหน้าระหว่างเปลี่ยนผ่าน) API `GET /api/patients` และ `GET /api/patients/export`

- **หนึ่งแถว = 1 visit ใน 1 กองทุน** visit ที่ไม่เข้าเกณฑ์กองทุนใด = 1 แถว "ไม่เข้าเกณฑ์" กองทุนแบบติดตามยอดรับ (FS, DRUG) แสดงเฉพาะเมื่อเลือกกองทุนนั้นในตัวกรอง
- **4 ขั้น** (กดเพื่อกรอง): ให้บริการ (ทุก visit ใน HOSxP) → เข้าเกณฑ์เบิก (ตามการตั้งค่ากองทุน) → ส่งเบิกแล้ว (พบใน REP) → ได้รับเงิน (REP จ่ายกองทุนนั้น) แต่ละขั้นแสดงจำนวนคน (ไม่ซ้ำ), visit, ยอดเงิน และ % ของขั้นก่อนหน้า
- **ติดปัญหา** (กดเพื่อกรอง แสดงจำนวนคนไม่ซ้ำ ชี้เพื่อดูจำนวน visit) แบ่ง 2 กลุ่ม
  - ทะเบียน: อยู่ในทะเบียนแต่ไม่พบใน HOSxP · มีใน HOSxP แต่ไม่อยู่ในทะเบียน (เฉพาะห้องที่ส่งทะเบียนครอบคลุมวันนั้น) · ยอดทะเบียนไม่ตรงกับ HOSxP
  - การเบิก: อยู่ใน REP แต่ไม่พบใน HOSxP · ติด C · เข้าเกณฑ์แต่ยังไม่ส่งเบิก · ส่งแล้วยังไม่ได้เงินกองทุน · ยอดต่าง (HOSxP–REP) · ได้เงินแต่ไม่เข้าเกณฑ์
- **ตัวกรอง:** ช่วงวันที่ · ห้อง/แผนก (มีค่าใช้จ่ายของห้องใน HOSxP หรือมีชื่อในทะเบียนห้อง) · กองทุน (รวม "ไม่เข้าเกณฑ์กองทุนใด") · ค้นหา ตัวกรองเก็บใน URL (`?dateFrom=&dateTo=&point=&fund=&step=&problem=&q=`) ส่งลิงก์ต่อได้ หน้าภาพรวมกดแถวกองทุนแล้วมาหน้านี้
- **ยอดเงิน** เปลี่ยนตามทุกตัวกรอง นับ visit ละครั้ง ถ้ากรองห้อง "ค่าใช้จ่าย" คือเฉพาะของห้องที่เลือก
- คอลัมน์ **ทะเบียน · HOSxP · REP** (v43 แทนคอลัมน์ขั้นตอน) จุด 3 จุดต่อกัน ทะเบียน → HOSxP → REP บอกว่าพบในแต่ละแหล่งหรือไม่ ใต้จุดบอกเรื่องที่ต้องตรวจ: เทา = ไม่มี · เขียว = มี · เหลือง = มีแต่ต้องตรวจ (ทะเบียน: ยอดไม่ตรง / ไม่พบใน HOSxP · HOSxP: ไม่เข้าเกณฑ์กองทุน · REP: ติด C / ยอดต่าง / ยังไม่ได้รับเงิน) กดหัวคอลัมน์เพื่อเรียง: ครั้งแรกพบน้อย/มีปัญหามากขึ้นก่อน กดอีกครั้งพบครบขึ้นก่อน แถวรูปแบบเดียวกันอยู่ติดกัน
- คอลัมน์ "ต้องทำอะไรต่อ" บอกงานจากปัญหาที่สำคัญที่สุด คลิกแถวดูทะเบียน / HOSxP (แยกห้อง) / REP (TRAN_ID, รหัสติด C และแนวทางแก้)
- ห้อง/แผนกตัดสินระดับ visit (ไม่ได้เก็บ dep_code ของรายการกองทุน) visit ที่ไปหลายห้องนับในทุกห้องที่ไป
- ปุ่ม "ดึงข้อมูล HOSxP ช่วงนี้" (ดึงตามช่วงวันที่ที่เลือก), ปุ่มอัปโหลดทะเบียนห้อง/แผนก และประวัติอัปโหลดอยู่ในหน้านี้
- **ความเร็ว (v37):** คำนวณทุก visit ของช่วงวันที่ครั้งเดียวแล้วเก็บไว้ในหน่วยความจำ (สูงสุด 4 ช่วงวันที่, 30 นาที) เปลี่ยนตัวกรอง/หน้า/การเรียงได้ทันที
  ล้างอัตโนมัติเมื่อข้อมูลเปลี่ยน (นำเข้า REP, ดึง HOSxP, อัปโหลด/ลบทะเบียน, แก้ตั้งค่ากองทุน ห้อง/แผนก หรือค่าบริการอัตโนมัติ)
  ปิด JIT ของ PostgreSQL ในการเชื่อมต่อของระบบ (`jit=off`) เพราะคำสั่งช่วงทั้งปีเสียเวลาคอมไพล์ JIT หลายวินาที (ทุกหน้ากระทบยอดเร็วขึ้นด้วย)
  ทดสอบ 117,000 visit (1 ปีงบ): เปิดครั้งแรกประมาณ 5–7 วินาที เปลี่ยนตัวกรองประมาณ 0.1–0.5 วินาที

## เทียบ 3 แหล่ง (ทะเบียน / HOSxP / REP) — มุมมองเดิม

หน้าเดียว ไม่ต้องเลือกห้องหรือกองทุน: ทุกทะเบียนในช่วงวันที่ที่เลือกเทียบกับ HOSxP และ REP พร้อมกัน **หนึ่งแถว = หนึ่ง visit**
(ไม่พบ visit = คนไข้ 1 คนใน 1 วัน) API `GET /api/registry/all` และส่งออก `GET /api/registry/all/export`

- กรองได้ 2 แบบ (ไม่บังคับ เลือกได้หลายรายการจาก dropdown ติ๊กถูก): **ห้อง/แผนก** = visit ที่มีทะเบียนของห้องนั้น หรือมีค่าใช้จ่ายของห้องนั้นใน HOSxP · **กองทุน** = visit ที่เข้าเกณฑ์กองทุนนั้นตามการตั้งค่ากองทุน (เกณฑ์เดียวกับหน้าแยกกองทุน OPD) (พารามิเตอร์ `point`, `fund` คั่นหลายรหัสด้วยจุลภาค เช่น `point=D005,P001`) ตัวเลขสรุป ปุ่มกรองผล และไฟล์ Excel คิดตามตัวกรองนี้ ผลการเทียบยังเป็นของทั้ง visit
- ตาราง 6 คอลัมน์: วันที่ · คนไข้ · ทะเบียน (ป้ายของทุกห้อง/แผนกที่บันทึก visit นี้ พร้อมเครื่องหมาย ตรง / ไม่ตรง / ไม่อยู่ในทะเบียน) · HOSxP (ยอดทั้ง visit) · REP (เรียกเก็บ ตัวเล็กเป็นได้รับ) · ผลการเทียบ
- ชี้หรือกดที่ยอด HOSxP: ป๊อปอัปค่าใช้จ่ายแยกตามห้อง (dep_code) และบอกว่าห้องนั้นตรงทะเบียน ไม่ตรง ไม่อยู่ในทะเบียน หรือไม่มีทะเบียน
- คลิกแถว: 3 กล่อง (ทะเบียนทุกฉบับ แสดงเฉพาะยอดในทะเบียนและผลเทียบ / HOSxP แยกห้อง / REP พร้อม TRAN_ID รหัสติด C และแนวทางแก้) และรายการจุดที่ต่างทั้งหมด
- ผลการเทียบ (เรียงจากเรื่องที่ต้องแก้ก่อน): ไม่พบ visit ใน HOSxP, ต้องจับคู่ชื่อรายการ, ทะเบียนไม่ตรงกับ HOSxP, ไม่อยู่ในทะเบียน, ติด C, ยังไม่พบใน REP, REP ไม่ตรงกับ HOSxP, ตรงกันครบ 3 แหล่ง
- "ไม่อยู่ในทะเบียน" นับเฉพาะห้อง/แผนกที่ส่งทะเบียนครอบคลุมวันนั้นแล้ว (ตามช่วงวันที่ของไฟล์ที่อัปโหลด) ห้องที่ไม่ได้ส่งทะเบียนไม่ถือว่าขาด
- ใช้เฉพาะ **ทะเบียนห้อง/แผนก (จุดบริการ)** ไม่ใช้ทะเบียนกองทุน (ตั้งแต่ v34) กองทุนของแต่ละ visit ดูจากการตั้งค่ากองทุนใน HOSxP แสดงในกล่อง HOSxP ทะเบียนกองทุนที่อัปโหลดไว้ก่อนหน้าไม่ถูกนำมาเทียบ
- ปุ่ม "อัปโหลดทะเบียน" เปิดหน้าต่างทะเบียนห้อง/แผนก ประวัติอัปโหลดอยู่ท้ายหน้า (`GET /api/registry/uploads`)
- REP เทียบระดับ visit ด้วยเกณฑ์เดียวกับหน้า "กระทบยอด OPD": เรียกเก็บ (HOSxP) (`uc_money`) เทียบ เรียกเก็บ (REP) ผลการจับคู่มาจาก `baseCte` ชุดเดียวกัน visit เดียวกันจึงได้ผลเดียวกันทั้งสองหน้า
  สถานะฝั่ง REP: ถูกปฏิเสธ / ติด C, ยังไม่พบใน REP, ยอดต่าง (HOSxP–REP) กล่อง REP มีลิงก์ "ดูในกระทบยอด OPD" (`/recon/opd?q=VN&dateFrom=&dateTo=`)
- สองเมนูแบ่งหน้าที่กัน: **กระทบยอด OPD** = งานเคลม (ทุก visit ส่งเบิกครบไหม ได้รับเงินไหม) / **เทียบ 3 แหล่ง** = งานหน้างาน (ทะเบียนลงใน HOSxP ครบและตรงไหม)

- **ค่าบริการอัตโนมัติ/ยา** (เช่น ค่าบริการผู้ป่วยนอก 50 บาท หรือค่ายา): ตั้งที่หน้า "จัดการห้อง/แผนก" (admin) เลือกรายการค่าบริการ (`nondrugitems`) หรือยา (`drugitems`) ทีละรายการ หรือติ๊ก "ยกเว้นค่ายาทั้งหมด" (ทุก icode ที่อยู่ใน `drugitems`, v45) หน้าจอแยกบรรทัด "ค่าบริการอัตโนมัติ X" และ "ยา Y" (คอลัมน์ `his_opd_dep.optional_drug_amount`, migration 021, v46 ต้องดึง HOSxP ใหม่) ระบบเทียบยอดทะเบียนห้อง/แผนกกับ HOSxP ทั้งแบบรวมและไม่รวมรายการเหล่านี้ ตรงแบบใดแบบหนึ่งถือว่าตรง
  ยอดของรายการเหล่านี้เก็บตอนดึงข้อมูล HOSxP (`his_opd_dep.optional_amount`) จึงต้องดึงใหม่หลังเปลี่ยนการตั้งค่า (หน้าจอจะเตือน) ค่าตั้งเก็บในตาราง `app_settings`
- ป๊อปอัปแยกห้อง: แผนกที่ผูกกับห้อง/แผนกเดียวกัน (เช่น 007 ห้องตรวจทันตกรรม + 007.1 ห้องซักประวัติทันตกรรม) แสดงเป็นกลุ่มเดียว สถานะทะเบียนเป็นของทั้งห้อง (ยอดรวมของทุกแผนกในห้องเทียบกับทะเบียน)

### คอลัมน์ยอดเงินในทะเบียน (v47)

ระบบหาคอลัมน์ยอดเงินจากชื่อหัวตาราง เช่น ราคา, จำนวนเงิน, ยอดรวม, ยอดเงิน, ค่าใช้จ่าย, ค่าบริการรวม, ค่ารักษา, บาท, รวม
คอลัมน์ชื่อ "ค่าบริการ" ที่ข้างในเป็นตัวเลขเกือบทั้งหมด (≥ 80%) และไฟล์ไม่มีคอลัมน์ยอดเงินอื่น ถือเป็นยอดเงิน (รุ่นก่อน v47 อ่านเป็นชื่อรายการ ทะเบียนจึงขึ้น "ไม่มียอด" ต้องอัปโหลดไฟล์เดิมใหม่)

### ทะเบียนกองทุน (ตามรายการค่าบริการ) — เลิกใช้ในหน้าเทียบ 3 แหล่งตั้งแต่ v34 (API ยังอยู่)

- คอลัมน์: วันที่ให้บริการ, HN, เลขบัตรประชาชน, ชื่อ-สกุล, รายการค่าบริการ (ชื่อรายการ) และราคา (icode, จำนวน ใส่เพิ่มได้ถ้ามี) จับคู่คนไข้ด้วย HN หรือเลขบัตร + วันที่ ระบบหาแถวหัวตารางเอง ดาวน์โหลดแม่แบบได้จากหน้าเดียวกัน
- HN ที่เป็นตัวเลขแต่ไม่ครบจำนวนหลัก เติม 0 ด้านหน้าให้ครบ (`HN_LENGTH` ใน `.env` ค่าเริ่มต้น 9)
- อัปโหลดใหม่จะแทนที่ทะเบียนของกองทุนนั้นในช่วงวันที่ที่ไฟล์ครอบคลุม
- จับคู่รายการ: icode ในไฟล์ → ชื่อที่เคยจับคู่ → ชื่อในการตั้งค่ากองทุน → ชื่อใน HOSxP (ต้องตรงรายการเดียว) ชื่อที่ไม่รู้จักให้เจ้าหน้าที่จับคู่ครั้งเดียว (ตาราง `item_aliases`)
- ต้องมีแค่วันที่ให้บริการและ HN (หรือเลขบัตร) รายการค่าบริการและราคาไม่บังคับ: แถวที่มีรายการเทียบระดับรายการ แถวที่ไม่มีรายการเทียบระดับ visit (มี visit ไหม เข้าเกณฑ์กองทุนไหม ได้รับเงินไหม)
- ผลการเทียบ: ตรงกันครบ, ยังไม่รู้จักรายการ, ไม่พบ visit, ยังไม่ลงค่าบริการใน HOSxP, มี visit แต่ไม่เข้าเกณฑ์กองทุน, ราคาไม่ตรง, ติด C, ยังไม่พบใน REP, ไม่ได้รับเงินกองทุนนี้, ไม่อยู่ในทะเบียน
- การดึงข้อมูล HOSxP ดึงรายการที่อยู่ในทะเบียนด้วย จึงควรดึงใหม่หลังอัปโหลดทะเบียน (หน้าจอจะเตือน)

## แถบสถานะข้อมูลและช่องวันที่

- แถบด้านบนทุกหน้าแสดงว่า REP / HOSxP / ทะเบียน อัปเดตล่าสุดเมื่อไร และข้อมูลถึงวันที่เท่าไร
  ถ้า HOSxP ยังไม่ครอบคลุมวันที่ใน REP หรือทะเบียนใหม่กว่าการดึงล่าสุด จะมีปุ่มดึงเฉพาะช่วงที่ขาด (API `/api/status`)
- ช่องวันที่ใช้รูปแบบ วว/ดด/ปปปป (พ.ศ.) ไม่ขึ้นกับภาษาของเบราว์เซอร์ พิมพ์ตัวเลขติดกันได้ (15092569) ปี ค.ศ. แปลงให้อัตโนมัติ มีปุ่มปฏิทิน

| เรียกเก็บ (HOSxP) | ยอดเรียกเก็บของ visit ใน HOSxP (`uc_money`) |
| เรียกเก็บ (REP) | ยอดเรียกเก็บใน REP |
| ได้รับ (REP) | เงินที่ได้รับตาม REP (ชดเชยสุทธิ หรือยอดกองทุน) |
| ตั้งเบิก (HOSxP) | ราคารวมของรายการค่าบริการที่เข้าเกณฑ์กองทุนใน HOSxP |

## เรียงตาราง

กดหัวคอลัมน์เพื่อเรียง (กดซ้ำสลับน้อยไปมาก / มากไปน้อย) ค่าว่างอยู่ท้ายเสมอ
ตารางแบ่งหน้า (กระทบยอด OPD, รายละเอียดแยกกองทุน, เทียบ 3 แหล่ง) เรียงที่เซิร์ฟเวอร์ ครอบคลุมทุกหน้า และไฟล์ส่งออกเรียงตามที่เลือก
คอลัมน์ที่เรียงได้กำหนดเป็น whitelist ใน `OPD_SORT`, `DETAIL_SORT`, `COMPARE_SORT` (backend) ตารางอื่นเรียงในหน้าเว็บด้วย `hooks/useSort.js`

### ทะเบียนห้อง/แผนก

สำหรับทะเบียนที่หน้างานสรุปยอดรวมต่อคนไข้ต่อวัน เช่น ทันตกรรม กายภาพบำบัด **ไม่ต้องตั้งค่าห้อง/แผนกล่วงหน้า**

- **เลือกห้อง/แผนกตอนอัปโหลด:** ในหน้าต่างอัปโหลด เลือกไฟล์ แล้วเลือกแผนกใน HOSxP (`opitemrece.dep_code`, ชื่อจาก `kskdepartment`) เลือกได้หลายแผนก
  ระบบเดาแผนกให้จากชื่อไฟล์ ชื่อชีต หรือหัวรายงาน (เช่น "ทะเบียนทันตกรรม.xlsx")
- **ระบบหา/สร้างห้อง/แผนกให้เอง:** แผนกชุดเดียวกัน = ห้อง/แผนกเดียวกัน (ไม่สนลำดับ) ถ้ายังไม่มีสร้างใหม่ ชื่อตามชื่อแผนก
- **ถ้ารายชื่อแผนกโหลดไม่ได้** (เช่น ยังไม่ได้ให้สิทธิ์ `kskdepartment`) หน้าต่างอัปโหลดแจ้งสาเหตุ แสดงรหัสแผนกที่พบในข้อมูลที่ดึงมาแล้ว และพิมพ์รหัสแผนกเองได้ มีปุ่มโหลดรายชื่อใหม่
- **เมนู "จัดการห้อง/แผนก" (admin):** ไม่บังคับ ใช้เปลี่ยนชื่อ รวมหรือแยกแผนก และกำหนดผู้รับผิดชอบ
- ทะเบียน: ไฟล์ละห้อง/แผนก คอลัมน์ วันที่รับบริการ, HN (หรือเลขบัตร), ชื่อ-สกุล, ยอดรวม (บาท) อัปโหลดใหม่แทนที่ทะเบียนของห้องนั้นในช่วงวันที่ของไฟล์
- ดึงข้อมูล HOSxP เก็บยอดค่าใช้จ่ายของทุก visit แยกตาม dep_code (ตาราง `his_opd_dep`)
- เทียบ 2 ชั้น: ทะเบียน กับ HOSxP เฉพาะแผนกของห้องนั้น (ต่างกันไม่เกิน 1 บาทถือว่าตรง) และ HOSxP ทั้ง visit กับยอดเรียกเก็บใน REP
- คนไข้ที่ไปหลายห้องใน visit เดียว: แต่ละห้องเทียบเฉพาะยอดของแผนกตัวเอง และรวมอยู่ในแถวเดียวกันของ visit นั้น
- สิทธิ์ HOSxP ที่ต้องเพิ่ม: `GRANT SELECT ON kskdepartment TO claim_reader;`

## นำเข้าไฟล์หลายไฟล์

หน้า "นำเข้าไฟล์ สปสช." เลือกหรือลากไฟล์ REP ได้หลายไฟล์พร้อมกัน (สูงสุด 50 ไฟล์) กด "ตรวจไฟล์ทั้งหมด" เพื่อดูสรุปทุกไฟล์
คลิกแถวเพื่อดูผลการตรวจละเอียดของไฟล์นั้น แล้วกด "นำเข้า" ระบบนำเข้าทีละไฟล์ ไฟล์ที่ล้มเหลวไม่กระทบไฟล์อื่น

## ส่งออกรายงาน

เมนู "ส่งออกรายงาน" ให้เจ้าหน้าที่ผู้รับผิดชอบกองทุนส่งออก Excel ไปใช้แก้ไขต่อ มี 6 ประเภท: คนไข้ที่เข้าเกณฑ์, ยังไม่ส่งเบิก, เคลมไม่สำเร็จ, ข้อมูลอาจไม่ครบถ้วน, ได้รับเงินแล้ว และได้รับเงินแต่ไม่เข้าเกณฑ์

- ไฟล์มีชีต "สรุป" (เงื่อนไขรายงาน ผู้ส่งออก จำนวนต่อกองทุน) และชีตข้อมูล แยกตามกองทุนได้ หัวตารางมีตัวกรอง
- คอลัมน์ "ประเด็นที่ควรตรวจ" รวมปัญหาที่พบ: ไม่มีเลขบัตร/ไม่ครบ 13 หลัก, ไม่มี PDX, ขาดรายการจำเป็น, ขาดรายการที่เคสได้รับเงินมักมี, ถูกปฏิเสธ
- คอลัมน์ว่าง "ผลการแก้ไข / หมายเหตุ" ให้เจ้าหน้าที่กรอก
- admin กำหนด "กองทุนที่รับผิดชอบ" ของผู้ใช้ได้ในหน้าผู้ใช้งาน หน้าส่งออกจะเลือกกองทุนเหล่านั้นไว้ให้ (ไม่ได้จำกัดสิทธิ์การดูข้อมูล)
- ทุกการส่งออกถูกบันทึกใน `access_logs`

## แดชบอร์ดภาพรวม (ตัวชี้วัด)

หน้าแรกแสดงตัวชี้วัดการเบิกของปีงบประมาณที่เลือก

| ตัวชี้วัด | วิธีคิด |
|---|---|
| อัตราการส่งเบิก | visit ที่เข้าเกณฑ์และพบใน Statement ÷ visit ที่เข้าเกณฑ์ |
| อัตราเคลมสำเร็จ | ได้รับเงิน ÷ ที่พบใน Statement |
| ความครบถ้วนของข้อมูล | visit ที่มีเลขบัตร 13 หลัก มี PDX และไม่ขาดรายการจำเป็น ÷ visit ที่เข้าเกณฑ์ |
| ยอดที่ยังไม่ส่งเบิก | ยอดตั้งเบิกของ visit ที่ไม่พบใน Statement (เดือนที่ปิดยอดแล้ว) |
| ยอดเบิกได้ | ยอดกองทุนจาก Statement ทุกรอบ |

- ตัวชี้วัดคิดเฉพาะ "เดือนที่ปิดยอดแล้ว" คือเดือนที่มีรายการใน Statement ที่นำเข้า เดือนที่ยังไม่มีแสดงเป็น "รอผล" เพราะ Statement มาช้ากว่าวันรับบริการ
- เป้าหมายตั้งได้รายกองทุนในหน้าตั้งค่ากองทุน (ค่าเริ่มต้น ส่งเบิก 95%, เคลมสำเร็จ 90%, ครบถ้วน 95%) สี: ถึงเป้า = เขียว, ต่ำกว่าไม่เกิน 10 จุด = เหลือง, ต่ำกว่านั้น = แดง
- ผลคำนวณถูกเก็บในหน่วยความจำ และคำนวณใหม่เมื่อมีการนำเข้า ดึงข้อมูล หรือแก้การตั้งค่า

## ติดตั้งใช้งานจริง

```bash
cp backend/.env.example backend/.env   # ตั้ง NODE_ENV=production และ JWT_SECRET ใหม่
docker compose up -d --build
docker compose exec app node scripts/seed.js
```

แอปเปิดที่พอร์ต 4000 (Express เสิร์ฟทั้ง API และหน้าเว็บ) ควรวางหลัง nginx ที่ใช้ HTTPS และตั้ง `TRUST_PROXY=1` ใน `.env` เมื่อใช้ production cookie จะถูกตั้งเป็น `secure` จึงต้องเข้าผ่าน HTTPS

## ความปลอดภัยและ PDPA

ข้อมูลไม่ออกนอกเครือข่ายรพ. ไฟล์ที่อัปโหลดประมวลผลในหน่วยความจำ ไม่เขียนลงดิสก์ token เก็บใน httpOnly cookie แบบ SameSite=strict มีการจำกัดการลอง login และทุกการดูผล ส่งออก นำเข้า และดึงข้อมูล ถูกบันทึกในตาราง `access_logs`

## งานถัดไปที่แนะนำ

ฝั่ง IPD (จับคู่ด้วย AN จาก `an_stat`), บันทึกการติดตามรายรายการ, กราฟแนวโน้มรายเดือน และนำเข้าหลายไฟล์พร้อมกัน
